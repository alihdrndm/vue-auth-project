# M1 — `einvoice`: detection, parsing and writing

## What was built

`backend/src/einvoice/` is a plain Python library with no Django, no Temporal and no OpenAI (import-linter contract `einvoice-is-pure`). It answers two questions about any received file: *what is it?* and *what does it say?*

- `detect.py` applies rules D1–D5 to the bytes, never to the file name: PDF or XML, hybrid or plain, text layer or scan. It then reads the profile from BT-24 and builds the format label the UI and the CSV show ("XRechnung · UBL", "ZUGFeRD · BASIC WL", "Scanned PDF").
- `pdf.py` pulls the embedded invoice XML out of a hybrid PDF (factur-x, with pypdf as fallback) and reads the text layer of the first six pages (pdfplumber).
- `parse_ubl.py` and `parse_cii.py` follow the XPath table in HANDOFF section 2 and produce one frozen `CanonicalInvoice` (`model.py`). Money is a `Decimal` with two places, never a float.
- `write.py` does the reverse. M2 will use it to build the sandbox samples.
- `tools/fetch_corpus.py` downloads the pinned ZUGFeRD corpus (Apache-2.0) and checks its SHA-256. `tools/check_coverage.py` enforces the per-package coverage thresholds.

## Key decisions

1. **One way to parse XML.** `xmlsafe.parse_xml` turns off entities, DTD loading and network access, and refuses any document with a DOCTYPE. factur-x parses PDF attachments with lxml's default parser *before* returning them, so `pdf.py` first runs every attachment through our safe parser, which honours any declared encoding, plus a decoded scan for UTF-8, -16 and -32. Only then does factur-x see it. The second review found the UTF-7 case that a byte scan alone missed. This is the Python counterpart of never passing user HTML to `innerHTML`: there is one sanitised entry point, and everything goes through it.
2. **Let the corpus check the XPaths.** The corpus contains the same 25 invoices in both UBL and CII. A test parses both and requires identical results on every field except `notes`. That cross-check verified the whole mapping table at once, without hand-writing an expected value for each XPath. All 172 ZUGFeRD 2 and XML-Rechnung files parse.
3. **Round-trip by property, not by example.** Hypothesis generates 200 invoices per syntax and proves `parse(write(invoice)) == invoice`. It found a real asymmetry: a tax number (BT-32) exists only for the seller. Seeing that, the CII parser and both writers now treat it the way the UBL parser already did.

## Measured

- `pnpm verify` passes: 203 backend tests. `einvoice` covers 99.1% of lines and 98.6% of branches (thresholds 90% and 85%).
- The full corpus run (172 files, PDF text included) takes about 15 seconds.
