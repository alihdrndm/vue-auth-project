# M8 — Frontend part 2, the homepage and the e2e stack

## What was built

- **Remaining app screens:**
  - **Approvals:** compact rows with the masked IBAN and its tag, inline Approve and Reject, with four-eyes and other disabled reasons shown as text.
  - **Suppliers:** a list, and a detail page with the IBAN history; an unconfirmed account links to the invoice whose C05 check confirms it.
  - **Exports:** format choice, the number of invoices ready, past exports with download.
  - **Settings:** organisation fields with the sandbox restrictions, members with a one-time password, and AI budget meters.
  - **Accuracy:** in the app and public, both from `GET /accuracy`; only measured numbers appear, never the design's samples.
- **The homepage:**
  - A hero and two interactive acts. Act 1: stamp sample documents by drag and drop or with a button, and watch Received → Processing → verdict. Act 2: resolve, mark reviewed, approve on the phone, export.
  - The facts with their sources, and the sandbox call to action.
  - Every motion has a reduced-motion end state.
- **Containers:**
  - `backend/docker/api.Dockerfile` and `worker.Dockerfile`; only the worker image carries SaxonC and the PDF libraries.
  - `frontend/Dockerfile` for the e2e stack.
  - A Compose `e2e` profile: a one-off setup service runs `migrate`, `seed_rules` and `ensure_schedules`; then the API, the worker and the web preview start, sharing one media volume.
- **Playwright:** the sandbox smoke test, plus homepage checks for axe, keyboard and the phone width. `pnpm test:e2e` runs them against a separate Compose project and always removes it.

## Key decisions

1. **The e2e stack is production-shaped.** It runs real images, with `DJANGO_DEBUG=false`, gunicorn, JSON logs and Secure cookies. The browser only talks to the web container, which proxies `/api`, exactly like Vercel in production. Problems that only show up in a built image show up here, not after deploying.
2. **Accessibility is tested, not assumed.** axe runs on the homepage at desktop and phone width and must report no serious or critical findings. It caught a 3.15:1 contrast on a warning chip, now fixed with the darker warning text colour. Both acts are also driven by keyboard in the test.
3. **Facts carry checked sources.** The design linked "BMF letter, 15 Oct 2024" to a software vendor's blog. The page links a published summary of the letter instead and says so, because the ministry's site refuses automated checks and its URL could not be verified.

## Measured

- `pnpm verify` passes, with more than 300 frontend tests and the backend gate.
- `pnpm test:e2e` passes headless: 5 tests, 15 s once the images are built. A cold image build takes about 3 minutes, and the stack is healthy about 47 s after start.
- Image sizes: API 537 MB, worker 811 MB, web 768 MB.
